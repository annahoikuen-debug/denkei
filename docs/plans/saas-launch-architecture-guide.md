# デンケイ (Denkei) 個人開発SaaS 公開＆運用アーキテクチャ設計書
## 〜 0円・極小コスト × 高セキュリティ × 手離れ（低保守）運用の実現 〜

本書は、日本の中小企業向け電子契約プラットフォーム「デンケイ（Denkei）」を、**初期費用・月額費用0円（または月1,000円前後の極小コスト）**で安全に公開し、**個人開発者が日々のインフラ保守に追われず手離れ良く運用・マネタイズするための実践ガイド**です。

## 2. 厳格チェック：矛盾点・セキュリティリスク・整合性の検証

個人開発において「0円だから」と安易に導入すると後から大トラブルになるポイントを洗い出し、対策を定義しました。

### ①【インフラの落とし穴】OCI Always Free の「アイドル停止」と「OOMビルド落ち」
* **リスク**:
  1. Oracle Cloud の Always Free は、CPU・メモリが一定期間低負荷（アイドル状態）だと**インスタンスが自動回収・停止**される規約があります。
  2. デンケイの Docker ビルドは `NODE_OPTIONS="--max-old-space-size=8192"` と指定されており、**ビルド時に最大8GBのメモリを要求**します。小規模サーバー上で直接 `docker compose build` すると確実にメモリ枯渇（OOM Killer）でサーバーが落ちます。
* **解決策（手離れ重視）**:
  * **ビルドは GitHub Actions（無料）に逃がす**: GitHub Packages (GHCR) にビルド済みコンテナイメージを置き、本番サーバーは `docker pull` して起動するだけにする。これで本番サーバーはメモリ1〜2GBでもサクサク動き、ビルド負荷ゼロになります。
  * **OCI アイドル回避**: 定期的なバックアップバッチやヘルスチェックが走るため通常は問題ありませんが、心配な場合は「Pay-As-You-Go（従量課金アカウント）」へアップグレード（無料枠を超えなければ請求0円のままアイドル回収が無効化）するのが最も安全です。

### ②【法務・プライバシー】特商法表記による「自宅住所・電話番号の流出」
* **リスク**:
  * SaaSでStripe決済（有料プラン・チケット販売）を行うには、日本の特定商取引法に基づき**「事業者名、所在地、電話番号」をWeb上に公開する義務**があります。自宅をそのまま書くとプライバシー事故になります。
* **解決策**:
  * **バーチャルオフィス / 050電話の利用**: 月額数百円〜千円程度のバーチャルオフィス（GMOオフィスサポート、NAZARU等）や、月数百円の050アプリを利用。
  * **特商法の遅滞なき開示の特例**: 一定条件下で「請求があれば遅滞なく開示する旨」を記載して住所を省略できる場合がありますが、Stripeの加盟店審査では実在する住所表記が求められることが多いため、安価なバーチャルオフィスの利用が最も確実で安全です。

### ③【メール送信の制限】Resend 無料枠（1日100通上限）とバースト送信
* **リスク**:
  * Resendの無料プランは「月3,000通」ですが**「1日100通」の上限**があります。契約1件あたり「依頼・OTP・完了」で平均3〜4通消費するため、1日に送れる契約数は実質20〜30件程度です。CSV一括送信などで100通を超えるとメールが不達になります。
* **解決策**:
  * 初期フェーズ（契約数が少ない時期）は Resend 無料枠（0円）で運用。
  * 契約数が増えて1日100通を超えそうになった時点で、**Amazon SES（1万通あたり約15円）**または Resend有料プラン（$20/月）に切り替える（売上の中から数十円〜数百円を支払う設計）。

### ④【データ保全・電帳法】PostgreSQL 内部ストレージの肥大化とバックアップ
* **リスク**:
  * `NEXT_PUBLIC_UPLOAD_TRANSPORT=database`（DB内包）のまま数百件のPDFを保存すると、DBのダンプサイズが巨大化し、バックアップとリストアが重くなります。
* **解決策**:
  * PDFストレージは **Cloudflare R2**（S3互換・10GB無料・下り転送量0円）または **Google Cloud Storage (GCS)**（5GB無料）へ外部化する。
  * DBにはメタデータと監査ログのみが残るため、DBサイズが数MB〜数十MBに収まり、日次バックアップが数秒で完了します。

## 3. 個人開発として「手離れ」を極限まで良くする3つの仕組み

個人開発で最も辛いのは「夜間の障害対応」「SSL証明書の更新切れ」「OSセキュリティパッチ作業」です。これを自動化・排除します。

### ① Cloudflare Tunnel（ポート開放不要・SSL更新不要・Nginx不要）
* サーバー側で `cloudflared` エージェントを1個動かすだけで、Cloudflareと暗号化トンネルで直結します。
* **メリット**:
  * VPSのポート（80/443/5432）をすべて閉鎖（ファイアウォール全閉じ）できるため、**不正アクセス・ポートスキャンが原理的に不可能**。
  * Let's EncryptのようなSSL証明書の自動更新エラーでサイトが落ちる心配がゼロ。
  * ルーターのポート開放や固定IPすら不要（自宅の余剰PCでも即SaaS化可能）。

### ② 毎朝4時の完全自動バックアップ（R2へ暗号化同期）
* 次の1行スクリプトを `cron` に登録するだけで、手動バックアップ作業から解放されます：
  ```bash
  # DBダンプ -> gzip圧縮 -> Cloudflare R2へ暗号化転送
  docker compose exec -T db pg_dump -U denkei denkei | gzip | aws s3 cp - s3://my-backup-bucket/denkei_$(date +%Y%m%d).sql.gz --endpoint-url https://<account_id>.r2.cloudflarestorage.com
  ```

### ③ Watchtower による自動コンテナ更新（オプション）
* GitHub Actionsで新バージョンがビルドされたら、サーバー側のDockerコンテナが自動で検知して安全に再起動・更新されるように設定可能。

## 5. 公開までのアクションチェックリスト（最短手順）

- [ ] **1. ドメインとCloudflareの準備**
  - [ ] 既存ドメインのサブドメイン（例: `sign.yourcompany.com`）をCloudflareに登録
  - [ ] Cloudflare Zero Trustで「Cloudflare Tunnel」を作成
- [ ] **2. 外部無料サービスのAPIキー取得**
  - [ ] **Resend**: アカウント開設 ＆ APIキー取得（送信ドメインのDNSレコードをCloudflareに追加）
  - [ ] **Firebase**: プロジェクト作成 ＆ サービスアカウントキーJSONをダウンロード
  - [ ] **Cloudflare R2**: バケット作成（`denkei-contracts`）＆ S3互換アクセスキー発行
  - [ ] **Stripe**: 本番申請 ＆ 商品（スタンダード2,980円、ビジネス4,980円、チケット1,500円/5,000円）のPrice ID取得
- [ ] **3. サーバー立ち上げ（OCI または 国内VPS）**
  - [ ] Ubuntu インスタンス作成 ＆ Dockerインストール
  - [ ] リポジトリをクローンし、`.env` に取得した各キーを設定
  - [ ] `docker compose -f docker/compose.standalone.yml up -d` で起動
  - [ ] Cloudflare Tunnel とコンテナ（localhost:3000）を接続
- [ ] **4. 法務ページの最終確認**
  - [ ] フッターに「特定商取引法に基づく表記」「利用規約」「プライバシーポリシー」を掲載
  - [ ] 1件テスト送信・署名・Stripe決済テストを実施して商用オープン！
